# Repository Skills

- [create-product-vision](create-product-vision/SKILL.md): discover, challenge, and record the authoritative Product Vision and hand off evidenced domain-term candidates
- [create-glossary](create-glossary/SKILL.md): establish authoritative domain terminology and apply only meaning-preserving editorial reconciliation to the Product Vision
- [create-domains](create-domains/SKILL.md): collaboratively discover and document strategic DDD domains, subdomains, and justified bounded contexts
- [create-actors](create-actors/SKILL.md): establish stable interacting roles and external participants without conflating them with stakeholders, personas, or permission roles
- [create-use-cases](create-use-cases/SKILL.md): collaboratively discover, map, visualize, and refine the actor-goal use-case catalog
- [specify-use-case](specify-use-case/SKILL.md): create, refine, correct, or assess one detailed Cockburn-style use-case specification
- [create-business-objects](create-business-objects/SKILL.md): discover and document conceptual business objects, lifecycles, relationships, and primary-subdomain responsibility
- [create-navigation-map](create-navigation-map/SKILL.md): collaboratively discover, map, visualize, and refine the product's information architecture and actor-facing navigation
- [create-wireframes](create-wireframes/SKILL.md): collaboratively create and evolve annotated low-fidelity interaction and state concepts, including optional browser-viewable HTML renderings
- [create-design-system](create-design-system/SKILL.md): collaboratively establish and evolve reusable experience principles, semantic foundations, patterns, components, and validation criteria
- [create-software-architecture](create-software-architecture/SKILL.md): derive and evolve technology-neutral modules, internal dependency structure, module contracts, coupling, consistency, and distribution strategy
- [create-entities](create-entities/SKILL.md): derive and evolve technology-neutral logical entities, value structures, relationships, integrity boundaries, and exactly one owning module per entity
- [create-technology](create-technology/SKILL.md): select and evolve a justified technology baseline with explicit usage boundaries, alternatives, compatibility policy, and validation
- [create-security-architecture](create-security-architecture/SKILL.md): derive and evolve protected assets, trust boundaries, threats, security responsibilities, control objectives, and verification expectations
- [specify-prototype](specify-prototype/SKILL.md): select a representative use-case slice, ensure sufficient detailed behavior, and specify a bounded prototype or PoC charter and evidence plan
