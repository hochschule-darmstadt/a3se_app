# Repository Skills

- [export-empty-harness](export-empty-harness/SKILL.md): export the reusable lifecycle harness as a clean, validated `new-project` starter without product artifacts, implementation, runtime state, or repository history
- [create-product-vision](create-product-vision/SKILL.md): discover, challenge, and record the authoritative Product Vision and hand off evidenced domain-term candidates
- [create-glossary](create-glossary/SKILL.md): establish authoritative domain terminology and apply only meaning-preserving editorial reconciliation to the Product Vision
- [create-domains](create-domains/SKILL.md): collaboratively discover and document strategic DDD domains, subdomains, and justified bounded contexts
- [create-actors](create-actors/SKILL.md): establish stable interacting roles and external participants without conflating them with stakeholders, personas, or permission roles
- [create-use-cases](create-use-cases/SKILL.md): collaboratively discover, map, visualize, and refine the actor-goal use-case catalog
- [specify-use-case](specify-use-case/SKILL.md): create, refine, correct, or assess one detailed Cockburn-style use-case specification
- [create-business-objects](create-business-objects/SKILL.md): discover and document conceptual business objects, lifecycles, relationships, and primary-subdomain responsibility
- [create-navigation-map](create-navigation-map/SKILL.md): collaboratively discover, map, visualize, and refine the product's information architecture and actor-facing navigation
- [create-wireframes](create-wireframes/SKILL.md): collaboratively create and evolve annotated low-fidelity interaction and state concepts, including optional browser-viewable HTML renderings
- [create-design-system](create-design-system/SKILL.md): collaboratively establish and evolve reusable experience principles, semantic foundations, patterns, components, and validation criteria
- [create-software-architecture](create-software-architecture/SKILL.md): derive and evolve technology-neutral modules, internal dependency structure, module contracts, coupling, consistency, and distribution strategy
- [create-entities](create-entities/SKILL.md): derive and evolve technology-neutral logical entities, value structures, relationships, integrity boundaries, and exactly one owning module per entity
- [create-technology](create-technology/SKILL.md): select and evolve a justified technology baseline with explicit usage boundaries, alternatives, compatibility policy, and validation
- [create-security-architecture](create-security-architecture/SKILL.md): derive and evolve protected assets, trust boundaries, threats, security responsibilities, control objectives, and verification expectations
- [create-deployment-architecture](create-deployment-architecture/SKILL.md): define and evolve environment landscapes, concrete runtime placement, isolation, configuration, data lifecycle, delivery boundaries, and environment specifications
- [create-test-strategy](create-test-strategy/SKILL.md): establish and evolve a risk- and evidence-based test baseline with proportionate levels, data and environment boundaries, human review, and readiness gates
- [create-ci-cd](create-ci-cd/SKILL.md): establish and evolve local verification, build, artifact, integration, promotion, deployment, evidence, and activation boundaries without implementing automation
- [create-coding-guidelines](create-coding-guidelines/SKILL.md): derive and evolve project- and technology-specific coding rules, patterns, examples, library references, optional quality skills, and verification mappings without changing governing baselines or executable configuration
- [create-technical-foundation](create-technical-foundation/SKILL.md): establish and evolve the executable repository, build, test, migration, configuration, local-environment, packaging, and verification mechanisms shared by delivery work
- [specify-prototype](specify-prototype/SKILL.md): select a representative fixed use-case slice and specify a bounded architecture-and-technology Prototype Charter and evidence plan
- [implement-prototype](implement-prototype/SKILL.md): implement a reviewed Prototype as one complete assignment with planning, tests, code, delivery, and evidence, as an optional alternative for stronger models capable of the combined complexity
- [plan-implementation](plan-implementation/SKILL.md): translate one reviewed Prototype Charter or Slice Manifest into ordered, executable implementation and evidence increments
- [create-tests](create-tests/SKILL.md): create and maintain the unit and integration tests required by one implementation-plan increment
- [create-code](create-code/SKILL.md): implement the product code, migrations, and scope-specific configuration required by one prepared increment
- [operate-ci-cd](operate-ci-cd/SKILL.md): execute the accepted verification and delivery path, capture raw evidence, and route failures without redefining the baseline
- [review-prototype](review-prototype/SKILL.md): assess declared architecture and technology hypotheses against current evidence without treating the Prototype as validation of business correctness
- [create-release-backlog](create-release-backlog/SKILL.md): derive and evolve a tracker-independent Release Backlog of evidence-backed Epics, Features, dependencies, sequencing, and planning questions with human confirmation
- [update-release-backlog](update-release-backlog/SKILL.md): reconcile iteration Stories, Slice links, and delivery evidence with affected Release Backlog Epics, Features, and outlook
- [create-sprint-backlog](create-sprint-backlog/SKILL.md): combine release priorities and delivery evidence with team-confirmed capacity and load to establish or replan one tracker-independent iteration backlog
- [specify-slice](specify-slice/SKILL.md): turn a selected Sprint Backlog Story into a coherent vertical Slice Manifest by coordinating the necessary authoritative artifact refinements and implementation-planning handoff
- [review-slice](review-slice/SKILL.md): assess one implemented Slice against its acceptance claims and completion conditions and record the bounded human review result

## A3SE-specific extension

- [commit-readiness](commit-readiness/SKILL.md): select and run proportionate checks for commits and pull requests under the A3SE commit workflow.
