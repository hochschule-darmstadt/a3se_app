Staff wireframes

Low-fidelity resource-management patterns. All records are synthetic. List, detail and edit states are shown together for review; permissions remain an open requirement.

The five managed-data areas are customers/travellers, touristic product catalogue, suppliers/partners, inventory and orders. Advice is contextual work, not a sixth master-data silo. The staff user icon in the header is explicitly mocked: no staff login exists yet, and this must not imply a real session (see Phase 1 notes in wireframes.md).

VIEW-S-003

Touristic product catalogue

Home / Touristic product catalogue

Every catalogue item is a TouristicProductItem per the entity model, recursive: a product may contain other products (e.g. a package containing a flight, a room category, and a guided tour) via the same CONTAINS relationship already implemented, so a "package" needs no separate type — it is any item with components (stakeholder decision, issue #31 phase 1). Each item's type (e.g. product/accommodation/room-category) selects its property schema; the create/edit form is type-driven. displayName is a new shared optional label (WF-Q-013) since no type carries a descriptive name today. Lifecycle is status-only in MVP — activating/retiring transitions the same record; there is no separate version history (WF-Q-014), so the low-fidelity "v3" label is dropped here.

VIEW-S-004

Suppliers and partners

Home / Suppliers and partners

Organisation (shared identity) and OrgaRole (contextual supplier role, e.g. partner/supplier/accommodation or partner/supplier/airline, with role-specific properties such as airlineDesignator) are separate entities per the entity model; one Organisation may hold multiple supplier roles (e.g. a group operating both hotels and transfers). This list/detail/edit shows both, not a flattened merge. The procurement negotiation itself (UC-006) is out of scope here; it belongs to #32's "Request supplier capacity" action, reached from a role's actions.
