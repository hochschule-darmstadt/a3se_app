- Status: draft
- Owner: Test
- Last reviewed: 2026-07-29

## Strategy

- Derive tests from accepted requirements, examples, rules, risks, architecture, and implementation—not from implementation alone.
- Use AI to propose cases, boundaries, failure modes, test data, and automation, then independently review coverage and oracles.
- Separate test generation from test evaluation where practical to reduce shared blind spots.
- Include functional, integration, contract, security, accessibility, performance, resilience, and operational tests proportionately.
- Use synthetic, privacy-safe data.

Maintain evidence of meaningful failures found, false confidence avoided, and AI-generated tests corrected or rejected. Technology-specific frameworks and coverage policies follow accepted stack decisions.
